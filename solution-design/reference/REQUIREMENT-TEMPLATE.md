# 需求模板（AI 高准确率识别）

设计原则：AI 对**固定字段名 + 受控值 + 稳定 ID** 的识别准确率远高于自由散文。本模板所有字段名、取值固定，可 grep、可校验、可跨工具解析，供 Step 3 即时落盘与后续工具消费。

## 清单头格式

《需求清单》开头必须带：

```markdown
# 需求识别 · <场景名>

- 日期：YYYY-MM-DD
- 场景卡：<谁> / <在什么情况下> / <要解决什么问题>
- 方向假设：升级 | 新开发 | 待判定
```

## 单条需求格式

每条需求一个 `### REQ-` 块，ID 全文唯一、永不复用：

```markdown
### REQ-<序号>：<一句话标题>

- 场景：<谁在什么情况下>
- 触发：<什么事件启动此流程>
- 输入：<数据 / 操作>
- 处理：<核心逻辑，一到两句>
- 输出：<结果 / 副作用>
- 验收：
  - Given <前置条件>，When <操作>，Then <预期结果>
- 优先级：P0 | P1 | P2
- 依赖：<REQ-xx / 无>
- 来源：<对话轮次或用户原话要点>
- 状态：已确认 | 待定 | 已排除
```

## 字段规范（受控，违反即格式错误）

| 字段 | 受控规则 |
|------|---------|
| 优先级 | 仅允许 `P0`（必须）/ `P1`（重要）/ `P2`（可选） |
| 状态 | 仅允许 `已确认` / `待定` / `已排除`；`已排除` 必须追加一行 `排除理由：<原因>` |
| 验收 | 至少一条 Given-When-Then；写不出 GWT 说明需求还没敲定，回到质询 |
| 依赖 | 只允许引用已存在的 REQ ID 或 `无` |
| 标题 | 一句话、可独立阅读、不含实现细节 |

## 示例

```markdown
### REQ-3：导出失败批次清单

- 场景：运维人员在批次处理结束后核对失败记录
- 触发：用户在批次详情页点击「导出失败清单」
- 输入：批次 ID、可选的时间范围
- 处理：查询该批次全部失败记录，生成 CSV 流式下载
- 输出：CSV 文件（表头固定 5 列）
- 验收：
  - Given 批次存在失败记录，When 点击导出，Then 返回含全部失败记录的 CSV
  - Given 批次无失败记录，When 点击导出，Then 按钮置灰不可点
- 优先级：P1
- 依赖：REQ-1
- 来源：Q4 轮用户确认「失败记录要能导出，Excel 能打开」
- 状态：已确认
```
